# 출퇴근길 버스 · v1.1

경복궁 → 3호선 하행 → 남부터미널역 → 남부터미널역(한일시멘트) → 한국제약바이오협회 경로의 **461, 641, 4319** 버스 도착판입니다.

출근도 지원합니다: **한국제약바이오협회(22248) → 남부터미널(22157) → 남부터미널역 → 3호선 상행 → 경복궁역**. 퇴근 승차 정류장은 **남부터미널·한일시멘트(22156)**입니다. 세 노선 모두 양방향 정류장 순서를 실제 서울 버스 API로 검증했습니다.

## 바로 실행

- **PC:** `PC 테스트.cmd`를 더블클릭합니다. 또는 PowerShell에서 `npm.cmd start`를 실행하고 http://127.0.0.1:4173 에 접속합니다. Node.js 20 이상이 필요합니다.
- **안드로이드:** `dist/homebound.apk`를 휴대폰으로 복사해 설치합니다. Android 8.0 이상을 지원합니다. 개인 테스트용 디버그 서명 APK입니다.
- 새 설치의 초기 상태는 **시뮬레이션**입니다. 기존 PC 설정과 키는 유지합니다. 가상 숫자에는 시뮬레이션 표시를 붙입니다. PC에서는 시간 제한 해제 테스트가 기본으로 켜집니다. 상단에서 **출근 / 퇴근 / 시간에 맞춰**를 선택할 수 있습니다.
- 기존 APK가 설치되어 있다면 삭제하지 말고 새 `homebound.apk`를 덮어 설치하세요. 같은 패키지와 서명을 사용하며 앱에 저장된 키와 설정을 유지합니다. PC의 키는 휴대폰으로 자동 복사하지 않습니다.

## 실시간 데이터 연결

1. 공공데이터포털에서 아래 **두 버스 서비스**의 활용신청 승인을 받습니다. 같은 계정의 서비스키를 사용할 수 있으나 두 서비스 모두 승인되어 있어야 합니다.
   - [서울특별시 정류소정보조회 서비스](https://www.data.go.kr/data/15000303/openapi.do): `stationinfo/getStationByUid`의 `arrmsg1`, `arrmsg2` 사용.
   - [서울특별시 노선정보조회 서비스](https://www.data.go.kr/data/15000193/openapi.do): `getBusRouteList`, `getStaionByRoute`로 노선 ID와 승차·하차 정류장 순서 확인.
2. [서울 열린데이터광장 지하철 실시간 도착정보](https://data.seoul.go.kr/dataList/OA-12764/A/1/datasetView.do)의 인증키를 발급받습니다. 버스와 다른 키입니다. 지하철 키 없이도 버스 조회는 가능합니다.
3. 앱의 **설정**에서 키를 입력하고 ‘실시간 · 서울 공공데이터’를 선택합니다. 버스 서비스키의 Encoding/Decoding 형식을 모두 처리합니다.
4. 설정에서 **활성화 시간 → 출퇴근 시간에만 / 24시간**을 선택합니다. 출퇴근 시간을 직접 바꿀 수 있습니다. 테스트 스위치를 끈 뒤 **알림 켜기**를 누릅니다. 안드로이드 알림 권한을 허용하고, 설정의 **자동 시작 권한 설정**에서 ‘알람 및 리마인더’를 허용합니다.

2026-10-08에 사용자가 입력한 키로 **출근·퇴근 버스와 지하철 상행·하행의 실제 응답을 확인**했습니다. 정류장 번호를 임의로 지정하지 않고 인증된 API에서 찾아 검증한 뒤 표시합니다. 네이버·카카오의 비공개 API는 사용하지 않습니다. 버스와 지하철 API는 공식 문서의 HTTP 주소를 사용합니다. 버스 호스트의 HTTPS 접속은 이 PC에서 응답하지 않았습니다. 안드로이드에서는 해당 두 교통 API 호스트에만 HTTP를 허용합니다. 지하철에는 일반 인증키가 아닌 실시간 지하철 인증키를 넣고, URL 대신 키 문자열만 입력하세요.

## 동작

- **출퇴근 시간에만:** 기본 출근 06:00–10:00, 퇴근 18:00–24:00. 시작 시각은 포함하고 종료 시각은 제외합니다. 주말도 포함하며 한국 시간 기준입니다. 출근 시작 < 출근 종료 ≤ 퇴근 시작 < 퇴근 종료 순서로 설정합니다.
- **24시간:** 시간 제한을 적용하지 않습니다. 상단 방향을 수동으로 고정하거나 자동 전환할 수 있습니다. 자동은 출근 구간에 출근, 퇴근 구간에 퇴근 방향이며, 구간 밖에서는 정오 전 출근·정오 이후 퇴근입니다.
- 설정한 시작·종료 경계의 정확한 알람을 예약하고 경계마다 시작/종료를 재평가합니다. 활성화 시간 안에서 알림을 켜면 즉시 시작합니다. 24시간 모드는 자정에도 알림을 유지합니다.
- 알림을 펼치면 **각 노선의 독립된 `분:초` 카운트다운**을 볼 수 있습니다. 접힌 알림의 요약 숫자는 API 갱신 시 업데이트됩니다.
- 기본 출퇴근 구간에서는 버스 API를 **60초마다** 조회합니다. 24시간 모드는 **100초마다** 조회해 약 864회/일로 호출량을 줄입니다. 시간을 길게 설정하면 활성화 시간의 총 길이에 맞춰 갱신 간격을 늘립니다. 세 노선은 한 정류장 응답에서 가져옵니다. 지하철은 화면에서 두 역을 버스 갱신 간격의 2배마다 조회합니다. 숫자는 조회 사이에도 1초마다 줄어듭니다.
- 원문에 초 정보가 있으면 초 단위 예측을 사용합니다. 분 정보만 있으면 ‘약’으로 표시합니다. `traTime1`을 초로 오인하지 않습니다. 도착예측이 지나가면 ‘도착예측 경과’를 표시하며 음수로 계속 세지 않습니다.
- 버스 조회 간격의 2배+15초 이상 갱신되지 않으면 ‘갱신 지연’을 표시하고 숫자를 숨깁니다. 오류가 발생해도 가상 정보로 전환하지 않습니다.
- 도착판은 선택한 방향의 **승차 정류장 기준**입니다. 출근은 제약바이오협회 정류장, 퇴근은 남부터미널·한일시멘트 정류장입니다. 위치 알림은 별도 선택 기능이며 탑승·하차 여부를 판단하지 않습니다. 3호선 `subwayId=1003`의 출근 `상행`, 퇴근 `하행`만 표시합니다.
- 출근 배차간격 **약 6분**은 사용자 제공 참고값으로 표시하며 실제 도착예측 계산에는 사용하지 않습니다. 시뮬레이션의 두 번째 버스는 첫 번째 버스보다 6분 뒤로 설정합니다.
- 시간 제한 해제 상태에서 안드로이드 알림을 켜면 15분간 테스트하고 종료합니다. 자동 실행 설정은 유지됩니다. **알림 중지**는 자동 실행도 끕니다.
- 화면이 꺼져도 갱신하기 위해 활성 세션 동안 제한 시간 있는 부분 wake lock을 사용합니다. 24시간 모드는 배터리를 더 사용합니다. 기종에 따라 앱 배터리 설정을 ‘제한 없음’으로 바꿔야 할 수 있습니다. 알림 중지 또는 활성화 시간 종료 시 wake lock을 해제합니다.
- 강제 종료하면 안드로이드가 알람을 막으므로 앱을 다시 열어야 합니다. 재부팅·시간 변경·앱 업데이트 뒤에는 예약을 복구합니다. 자동 시작 권한이 없으면 앱을 열고 수동으로 알림을 시작할 수 있습니다.

## 역·정류장 300m 진입 알림 (1.2.0)

1. 새 APK를 기존 앱에 덮어 설치하고 설정에서 **역·정류장 반경 300m 진입 알림**을 켠 뒤 저장하세요.
2. **위치 권한 설정**에서 먼저 ‘정확한 위치’를 허용하세요. 다시 버튼을 눌러 앱 권한 → 위치 → **항상 허용**으로 변경합니다. 알림 권한도 허용하고 **알림 켜기**로 전체 알림을 활성화합니다.
3. **팝업 알림 설정**에서 ‘정류장·역 300m 진입 알림’ 채널의 팝업/화면에 표시 옵션을 확인하세요. 휴대폰 제조사에 따라 명칭이 다릅니다. 방해 금지나 채널 설정 때문에 상단 팝업이 생략될 수 있습니다.
4. **300m 진입 팝업 테스트**는 선택한 장소에 대한 일회성 테스트 알림입니다. 안드로이드는 시스템 알림, PC는 화면 팝업을 표시합니다. 실제 GPS 진입이나 활성화 시간 제한을 검증하는 버튼은 아닙니다.

경복궁역, 남부터미널역, 양방향 버스 정류장(남부터미널·한일시멘트 22156 / 남부터미널 22157 / 한국제약바이오협회 22228·22248)을 등록합니다. 위치 감지는 Google Play 서비스의 지오펜싱을 사용하며 별도 서버나 지도 API 키가 필요하지 않습니다. Google Play 서비스가 없는 기기는 위치 알림을 사용할 수 없습니다. 위치 좌표와 이동 기록을 저장하거나 서버로 전송하지 않습니다. 중복 억제를 위해 장소별 진입 상태와 마지막 알림 시각만 기기에 저장합니다.

선택한 출근·퇴근 방향과 활성화 시간(출퇴근시간 / 24시간)을 따릅니다. 활성화 시간 밖의 진입 이벤트는 팝업을 표시하지 않습니다. 시간 경계에서 이미 구역 안에 있는 경우도 재평가하며 자동 시작 권한이 필요합니다. 남부터미널역과 근처 버스 정류장은 같은 구역으로 묶어 반복 알림을 억제합니다. 한 구역에 머무르면 다시 울리지 않으며, 벗어나 재진입해도 마지막 알림 이후 최소 15분이 지나야 다시 알립니다. 출근·퇴근 버스 승차 지점에서는 최근 조회가 유효하면 버스 도착예측도 표시하며, 조회가 없거나 오래됐으면 앱에서 확인하도록 안내합니다.

300m는 좌표 기준 직선 반경입니다. 지하·터널, GPS 오차, 위치 서비스 설정, 절전 정책 때문에 정확한 경계에서 즉시 울린다고 보장할 수 없습니다. 안드로이드 백그라운드 지오펜싱은 수분 지연될 수 있습니다. 강제 종료 후에는 앱을 다시 열어야 합니다. [안드로이드 지오펜싱 문서](https://developer.android.com/develop/sensors-and-location/location/geofencing).

좌표는 2026-10-08에 [서울시 지하철역 GEOM 자료](https://t-data.seoul.go.kr/dataprovide/trafficdataviewfile.do?data_id=36)의 원본 CSV와 인증된 서울 버스 노선 API에서 확인했습니다. 경복궁역 37.575762 / 126.973530, 남부터미널역 37.485013 / 127.016189이며 `web/places.json`에 정류장 좌표와 함께 관리합니다. 자료 제공: 서울특별시 교통정책지원시스템(TAIMS), 서울특별시 버스정보시스템.

## 키 저장 위치

안드로이드에서는 앱 전용 SharedPreferences에 저장하고 앱 백업을 끕니다. PC에서는 `.local/settings.json`에 로컬 저장하며 Git에서 제외합니다. 설정 API는 키의 존재 여부만 반환하고 실제 키를 화면으로 반환하지 않습니다. `.local` 경로는 웹으로 노출하지 않습니다. 필요하면 설정에서 ‘저장된 키 삭제’를 누릅니다. 키는 PC와 휴대폰에서 각각 입력합니다.

## 개발 및 검증

```powershell
npm.cmd ci
npm.cmd test
npm.cmd start
# 다른 터미널에서
npm.cmd run test:ui
.\build-android.ps1
# USB 디버깅 기기에 설치하려면
.\build-android.ps1 -Install
```

`android` 폴더를 Android Studio에서 열어도 빌드할 수 있습니다. 로컬 `tools`에는 이번 작업에서 구성한 JDK 17, Gradle 8.11.1, Android SDK 35가 있습니다. SDK는 Git에서 제외합니다. `specialUse` 포그라운드 서비스 유형으로 사용자가 켠 지속 도착판을 실행합니다. Google Play 배포 시 해당 사용 사례 심사가 별도로 필요합니다. 현재는 개인 설치용이며 Play 배포는 하지 않았습니다.

테스트는 오전·저녁·자정 경계, 24시간 모드, 사용자 지정 시간, 방향 선택, 지하철 상·하행 필터, 호출량, 도착 메시지, 정류장 방향, 오류 처리, 반응형 화면, 설정 저장, 키 비공개, 안드로이드 브리지 호출, 위치 팝업 미리보기와 권한 설정 호출을 검증합니다. UI 테스트는 별도 설정 파일과 별도 서버를 사용해 실제 저장된 키를 변경하지 않습니다. 자바 시간 예약 로직과 위치 알림 중복 억제·재진입 규칙도 독립 실행으로 검사합니다. 화면 캡처는 `test-results`에 있습니다. 실제 휴대폰의 GPS 진입 감지, 배터리 정책과 예약 자동 시작은 실기기에서 추가 확인해야 합니다. 위치 라이브러리는 현재 AGP의 정적 검사와 호환되는 Google Play services location 21.3.0을 사용합니다.

데이터 출처: 서울특별시 TOPIS / 공공데이터포털 / 서울 열린데이터광장.
