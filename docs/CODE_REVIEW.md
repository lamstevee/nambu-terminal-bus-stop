## P2 · 교통 API 인증키가 HTTP로 전달됨

- 위치: `lib/transit.mjs:51,83`, `android/app/src/main/java/kr/homebound/nambu/TransitApi.java:62,153`.
- 버스 키는 쿼리 문자열, 지하철 키는 URL 경로에 포함되며 HTTP로 요청합니다. 네트워크 경로에서 키와 응답을 읽거나 변조할 수 있습니다. 로컬 서버의 접속 제한만으로 외부 API 전송을 보호하지는 못합니다.
- 개선: 공급자의 현재 HTTPS 지원을 확인하고 연결 검증 후 전환합니다. 지원하지 않는 경우 제공자 측 전송 보안 제약을 명시합니다. 이번에는 외부 엔드포인트 지원 여부를 검증하지 않았습니다.

## P2 · 서버 연결 중단 시 지하철 갱신 지연 표시가 멈춤

- 위치: `web/app.js:69,78-82,126`.
- 지하철 데이터 유효기간 판단은 `render()`에서만 수행됩니다. 성공한 조회 뒤 PC 서버를 종료하면 `refresh()`의 예외 경로는 오류 문구만 변경하고, 1초 타이머는 `renderBuses()`만 호출합니다. 버스와 달리 지하철에는 오래된 도착 문구가 계속 남습니다.
- 재현 조건: 실시간 지하철 응답을 받은 뒤 서버를 중지하고 `pollSeconds × 4 + 15`초 이상 기다립니다. 정적 코드 경로로 확인했으며 실제 API를 이용한 재현은 하지 않았습니다.
- 개선: 지하철 신선도도 주기적으로 재평가하거나 조회 실패 시 오래된 정보 표시를 함께 갱신합니다.

Java 검사는 JDK 17의 `javac -encoding UTF-8`로 정책 및 검사 클래스를 함께 컴파일했습니다. Windows 기본 인코딩으로 실행한 최초 컴파일은 실패했고 UTF-8 지정 후 통과했습니다.

업로드 텍스트와 APK의 assets/DEX에서 일반적인 인증키·개인키 패턴 후보는 발견되지 않았습니다. 포괄적 보안 감사나 APK 전체 역공학 검증은 아닙니다. `.local`, `.env` 등 제외 대상은 공개하지 않습니다.
